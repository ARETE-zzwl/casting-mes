# 登录与业务授权推进记录

## 状态

本轮修改独立整理目录，原免登录演示项目和业务数据没有覆盖。许可证为 Apache-2.0；开源范围仅包含源码，运行库、验收截图和附件保留本地。

真实网页登录、附件自动授权和现有业务模块的岗位鉴权已完成本轮验收。既验证正常岗位能推进业务，也验证身份冒用、跨员工、跨产线、重复请求和敏感字段隔离。此结论针对下列明确测试范围，不表示所有现场情况已穷举，也不代表公网部署环境已经验收。

## 真实登录

- `secure`：本地账号与服务端会话，不依赖外部身份提供方。
- `prod`：保留 JWT issuer/subject 绑定，同时支持本地账号会话。
- 无自行注册。管理员先建员工、分配角色和数据范围，再初始化密码。默认不强制首次修改，用户可主动修改密码。
- 未初始化账号不能登录。仅 A001 可以由 `MES_BOOTSTRAP_ADMIN_PASSWORD` 首次创建密码，已有账号不会被启动参数覆盖；初始化后移除该变量。
- 最少 12 个字符、UTF-8 不超过 72 字节，BCrypt 12。连续 5 次错误锁定 15 分钟，失败计数独立提交。
- 会话 HttpOnly、SameSite=Lax、30 分钟闲置超时，登录/改密轮换会话 ID。每次请求验证员工是否启用和密码版本，重置密码立即撤销旧会话。
- Cookie 写操作要求 CSRF，登录也不例外。前端不会自动重放失败的业务写操作，不在 localStorage 保存认证令牌；浏览器存储的演示工号不能改变登录身份。
- 管理员页面显示账号是否已初始化及最近登录时间，密码不回显。

### 本机验证启动

在独立测试目录中设置 `SPRING_PROFILES_ACTIVE=secure` 和一次性管理员密码环境变量。仅本机 HTTP 联调时设置 `MES_COOKIE_SECURE=false`，监听地址保持 127.0.0.1。然后依照 README 启动后端和前端。

PostgreSQL 联调使用 `secure,postgresql`，配置 `MES_DATABASE_URL`、`MES_DATABASE_USERNAME`、`MES_DATABASE_PASSWORD`。正式 HTTPS 环境保留 Secure Cookie，禁止复用本轮隔离测试库的信任认证设置。此步骤是验证环境启动说明，不表示已经批准公网生产部署。

演示迁移包含多角色账号，例如 S001 仍兼工程师。管理员开通生产账号前必须核对所有角色，不能只看主角色名称。权限按实际多角色叠加，不应擅自删掉用户配置的副角色。

## 本轮授权范围

| 范围 | 新增约束 |
| --- | --- |
| 订单 | 前台录入/修改/提交，客户经理或总经理复核，工程师确认/退回；调用者字段须与会话一致 |
| 订单读取 | 单岗位主管限制产线；工程师/业务管理岗位按职责读取；工程师、生产主管响应不包含成交价和合同地址 |
| 任务 | 列表即使不传筛选也受服务端范围限制；直接猜任务 ID、跨产线、跨员工访问拒绝 |
| 报工/领取 | 查看工作台不代表可报工；写入须 TASK_EXECUTE，自领须 TASK_SELF_CLAIM，业务状态检查仍保留 |
| 工艺资料 | 模板创建/发布限工程岗位，产品维护按资料权限；上传人与操作工身份不能通过请求字段冒用 |
| 仓储 | 原材料既有范围校验保留，补充模具和成品相关路由；成品登记 registeredBy 必须是真实调用者 |
| 工资 | 工价、候选、确认、个人工资与产出、CSV 导出按主管产线/工序范围过滤；财务按职责核算全厂；普通操作工不得使用全厂工资接口；已确认记录重试仍检查范围 |
| 炉次 | 每个关联任务都须属于调用者范围；创建、读取、关闭分别检查对象，混入一条越权任务时整体拒绝，无部分写入 |
| 外协 | 发出任务、进度和来料检验与外协单关联；禁止跨线读写台账；检验未完成不能关闭；砂型末道检验完成后，成品仓可接收入库 |
| 扫码 | 根据调用者分派/可领取范围返回任务和批次工序；隐藏范围外对象；扫码意图、实体、编码必须对应，操作者不可伪造；扫码定位不等于自动接收 |
| 周转车 | 来源与接收任务分别鉴权；装车来源由独立接口查出，不要求员工拥有下一道任务读取权；来源任务加锁防超装；重复操作号不能变更数量或返回其他流转 |
| 纸质报工 | 真实主管代录、范围内审核，工资归属必须为已派执行员工；电子流水分别记录实际员工和代录者；拒绝负数、零产出、非整数件数和不合法工时 |
| 离线报工 | 待传计数与重传按当前员工隔离；其他账号记录保留但不代传；同账号合并并发重传，保留操作号，重传期间新增记录不会被覆盖 |
| 异常/排产 | 交接异常在数据库分页和总数查询前应用任务范围；异常指派/关闭及排程调整检查任务写权限；质检和调度的只读看板不返回工资金额 |
| 打印 | 通用 entityId 同样进行订单/任务范围校验；岗位页面仅请求其允许的业务依赖；打印字段及审计权限独立检查 |
| 自定义审批 | 由模板确定审批次数和审批岗位，不能从客户端降低要求；申请人与审批人分离，列表和动作按职责限制；普通参与者不能管理管理员配置 |
| 消息 | 查看和已读只能操作本人通知 |
| 账号 | 管理员初始化/重置，普通员工不能编辑角色、账号或借用管理员 viewerCode |

核心接口策略在 `ProductionRoutePolicy`，对象范围集中于 `BusinessAccess` 并由业务服务补充检查。`AuthorizationRouteCoverageTests` 遍历实际业务路由，新接口没有明确策略时测试失败；模拟清库接口在受控配置中禁用。管理员配置和维护接口仍保留管理员限制，这属于岗位设计，不是漏开放。

JWT 的管理员 scope 和数据库管理员角色必须同时满足。即使同一账号兼主管与管理员，只有普通 JWT scope 时也不能借数据库管理员角色扩大工资、报工、排产、打印或销售读取范围。本地账号会话按受控管理员身份判断。二维码绑定也按资产类型校验：周转车人员不能绑定模具，重复绑定同样检查权限。

## 附件业务授权

- 合同：只对上传人、显式授权者和已关联订单的商务岗位开放；不因拥有工单或主管身份自动开放。
- 订单图纸：关联订单的工程/业务岗位、授权产线主管及已派任务员工可读。
- 产品图：已关联产品资料的管理岗位、对应任务员工可读。
- 工艺图：按任务工序读取工作单快照的 `_operationImages`；不是给员工整个工艺库的读取权限。
- 报工照片：当前任务及下一道已派任务可读；分批流转、交接和推车关联字段也纳入查询。
- 每次访问依据当前数据库关系判断，改派后旧员工不会继续继承业务授权。上传人自身及 DBA 显式读者属于独立授权，仍可读。
- 写入附件引用前先检查可读权限与分类；仅猜中他人的私有 URL 不能通过绑定产品把附件公开。
- 无 stored_attachment 元数据的旧文件依然拒绝访问，禁止为解决旧图片问题直接恢复静态公开目录。

纸质单图片引用已纳入业务授权。旧库附件补建元数据、全厂历史格式及大数据量下的授权查询性能仍需用实际存量数据演练；不得为兼容旧文件而放开整个附件目录。

## 部署边界

1. 本轮模块鉴权验收已完成；实际工厂账号、组合角色和数据范围仍须由管理员核对后开通，不能直接照搬演示多角色账号。
2. 全厂存量数据及历史附件元数据迁移、容量压力、真实身份提供方和 HTTPS 反向代理环境需要部署专项验收。
3. 微信原生小程序和 OIDC 前端不是本轮已验证功能，移动截图是响应式网页；当前可用登录方式是本地账号会话，后端保留 JWT 对接。
4. 当前依赖无已知漏洞不等于不存在漏洞，生产需要持续更新审计；真实断电和存储硬件故障不等于进程重启测试。
5. 离线队列保存本机待传数量和任务标识，不存登录令牌；它不是加密存储。清理浏览器数据会丢失未上传记录，不能替代纸质记录或数据库备份。

Apache-2.0 源码与本地演示不构成生产安全保证。数据库、合同、账号密码和测试图片不随源码发布。
