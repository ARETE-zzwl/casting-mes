# 查询性能、拆批追溯与页面加载审查

日期：2026-10-03。仅修改开源源码目录；原免登录测试版及其业务数据不变。验证使用独立数据库和测试夹具，没有清洗、迁移或覆盖实际订单。

## 已落实

| 项目 | 改动 | 验证口径 |
| --- | --- | --- |
| 订单追溯 N+1 | 计划模块批量提供工单、批次、任务；报工模块分组读取报工；继续由追溯模块组装 | 两产品、不同材质、多个批次、报工归属、时间顺序、草稿及不存在订单 |
| 拆批上游关系错误 | 仅拆批首道继承原任务；后续工序读取本批前一道；保留拆出时间上限 | 原组树任务错误读取射蜡记录的断言先失败，修复后通过；后补的来源报工不进入先行批次 |
| 模块查询归属 | 上游关系查询移回 planning，execution 只读取报工事实 | 3 项架构检查及生产回归通过；不宣称其他跨模块 SQL 已清除 |
| 前端首包 | 原有 3 个懒加载页面扩展到全部业务路由，登录与导航保持即时加载 | 构建 manifest 静态依赖总量门禁，角色切换与路由保护单元测试 |
| 页面加载失败 | 页面级错误边界，导航不消失，可切其他页面或手动重试 | 桌面 1440px 和手机 390px 的构建产物断网演练 |

没有引入微服务、消息中间件、全局权限缓存或新的生产运行依赖；没有变更数据库结构和历史迁移。

## 量化对比

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 2 产品 / 2 批次 / 22 任务追溯 SQL | 37 | 9 |
| 2 产品 / 20 批次 / 220 任务追溯 SQL | 307 | 9 |
| 入口 JS（包括递归静态依赖） | 801,914 B | 321,498 B |
| 同上 gzip | 223,086 B | 99,161 B |

SQL 统计由测试数据源代理覆盖 JPA 和 JDBC，只统计当前线程的 `traceOrder` 应用调用；不包括 HTTP 身份校验、输出脱敏和网络。H2 与 PostgreSQL 的修改后结果相同。查询预算为 20 批次不超过 12 次，且相对 2 批次增长不超过 2 次。任务超过 500 个时，报工查询按 ID 分块增加，不是所有订单永久固定 9 次。

入口原始体积减少约 60%，gzip 减少约 56%；这不是实际网络延迟减少比例。访问某一功能时仍需下载该功能代码。图表包约 574 KB，仍有构建体积提示；本轮没有关闭或放宽提示。

## 验证结果

- 后端完整 `mvn verify`：58 个测试类、154 项通过，0 失败、0 错误、0 跳过，JAR 构建通过。
- PostgreSQL 17.11：11 个测试类、26 项通过。新增追溯查询预算和完整生产拆批场景加入 CI；日志未使用 H2。
- 前端：17 个文件、48 项 Vitest 通过，TypeScript、Vite 和入口体积预算通过。
- 构建产物加载专项：真实后端的匿名登录页只请求入口 JS；失败恢复场景使用明确的前端 API 夹具，桌面和手机均完成页面切换、模拟 chunk 下载失败、保留导航、切换后恢复以及刷新重试，无未捕获页面错误、无水平溢出。
- 真实登录多角色业务验收：独立 PostgreSQL 数据库、`secure` 后端和 Vite 构建产物，41 个账号、188 项业务检查、445 次页面检查通过，覆盖 410 个不同的账号/路径组合；预期外接口失败、页面异常及移动端横向溢出均为 0。

业务验收包括三条产线、组树/制壳/炉次、推车交接、纸质回填、成品入库交付、工资导出和越权拒绝。登录、部分手机端接收/开工/报工通过浏览器点击；其余业务步骤使用同一已登录浏览器会话的 API 请求，不能描述为所有步骤都手动点击。页面巡检实际加载全部导航目的地，包含文档页。没有覆盖每种打印机、外设扫码枪和全部工厂存量数据。

Better Design 的 UI、UX 与复查请求均因服务配额耗尽返回 402。本轮保留已有工业 UI 与图标，没有改设计系统；已实际查看桌面/手机失败与恢复截图，不能将工具调用失败写作设计审查通过。

本地证据在忽略目录 `artifacts/`：`trace-query-before.log`、`query-and-upstream.log`、`trace-query-final.log`、`upstream-before.log`、`review-20261003-backend.log`、`review-20261003-postgresql.log`、`review-20261003-chunks/`、`review-20261003-browser/`。日志、业务测试数据和截图不随公开源码上传。

## 保留边界

1. 授权层、报表和其他业务仍有跨模块表查询，本轮只收回上游关系查询的所有权，后续按业务分项迁移。
2. 大订单响应体和任务列表仍需独立做分页及内存预算，本轮没有用截断数据换取性能指标。
3. 移动端验收是响应式 Web，不是微信原生小程序验收；弱网首次下载新页面仍需要网络。
4. 生产部署保留旧哈希资源一段时间并让 HTML 及时刷新，避免发版后已打开的客户端找不到旧 chunk；应用重试入口不能替代部署时的资源保留策略。
